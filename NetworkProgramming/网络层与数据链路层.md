# IP协议

IP协议属于网络层
## 组成

|字段|作用|
|---|---|
|版本（Version）|标识IP协议版本，如IPv4。|
|首部长度（IHL）|表示IP首部的长度。|
|服务类型（ToS）|指定数据包的服务质量和优先级。|
|总长度（Total Length）|表示IP数据包的总长度，包括首部和数据。|
|标识（Identification）|用于标识数据包，便于分片重组。|
|标志（Flags）|控制数据包是否允许分片及是否还有后续分片。|
|片偏移（Fragment Offset）|指示分片在原始数据包中的位置。|
|生存时间（TTL）|限制数据包经过的路由器跳数，防止无限循环。|
|协议（Protocol）|标识上层协议，如TCP、UDP、ICMP。|
|首部校验和（Header Checksum）|检测IP首部在传输过程中是否发生错误。|
|源IP地址|标识发送方的IP地址。|
|目的IP地址|标识接收方的IP地址。|
|可选字段（Options）|提供特殊控制功能，如时间戳、路由记录等。|
|填充（Padding）|保证首部长度为32位的整数倍。|
## 网段划分

IP地址总长为32位, 划分为两个部分: 网络号与主机号: 
1. A类: 7位网络号, 24位主机号, 0.0.0.0到127.255.255.255
2. B类: 14位网络号, 16位主机号, 128.0.0.0到191.255.255.255
3. C类: 21位网络号, 8位主机号, 192.0.0.0到223.255.255.255
4. D类
5. E类

## 子网掩码
由于A, B类IP中有大量主机号, 很少有子网中含有大量主机. 故浪费了大量IP. 
为了充分利用IP地址, 标准组织提出了新的网络号与主机号划分方案: 子网掩码
1. 子网掩码是一个32位整数, 通常用一串 "0" 来结尾
2. 将IP地址和子网掩码进行 "按位与" 操作, 得到的结果就是网络号
3. 网络号和主机号的划分与这个IP地址是A类、B类还是C类无关
*子网掩码使IP地址能够被充分利用, 但是无法解决IP地址总体数量不足的问题*
### 特殊的IP
- 将IP地址中的主机地址全部设为0, 就成为了网络号, 代表这个局域网
- 将IP地址中的主机地址全部设为1, 成为了广播地址, 用于给同一个链路中相互连接的所有主机发送数据包

## NAT技术

NAT（Network Address Translation，网络地址转换）技术是一种将私有IP地址转换为公有IP地址的技术，主要用于解决IPv4地址不足的问题。
**工作原理**: 
当局域网内的设备访问互联网时，NAT设备（通常是路由器）将数据包中的私有IP地址转换为公有IP地址，并记录映射关系。当收到返回数据时，再根据映射关系将目的地址转换为对应的私有IP地址。

## 私有IP与公网IP

如果一个组织内部组建局域网,IP地址只用于局域网内的通信,而不直接连到Internet上,理论上 使用任意 的IP地址都可以,但是RFC 1918规定了用于组建局域网的私有IP地址的规则

借助NAT技术, 一个IP地址可以同时被多个子网中的主机使用. 子网中的IP地址不能重复. 

**NAT技术与私有公有IP的实现**
- 一个路由器为当前局域网中的每个主机分配私有IP. 
- 当私有IP访问公网时, 路由器将报文中的私有IP转换为路由器的IP(替换成WAN口IP)并向上传递. 
- 每次转换时, 路由器中会保留有目标IP与源IP以及其端口的映射关系, 否则报文回传时将找不到目标. 
- 逐层替换直到到达公网. 公网入口路由拥有公网IP. 公网IP是唯一的. 

**注意**: 每次转换的映射关系中必须含有源IP的端口号. 多个内网主机可能共享同一个公有IP地址; 例如: 

| 内网IP及端口           | 转换后的公有IP及端口      |
| ----------------- | ---------------- |
| 192.168.1.10:5000 | 202.100.1.1:6001 |
| 192.168.1.20:5000 | 202.100.1.1:6002 |

如果只记录IP地址，NAT设备就无法判断收到的数据应该转发给哪台主机。

## 路由

1. 每个路由器中维护了当前其内部的每个主机的信息, 称为路由表.
2. 当IP数据包到达路由器时, 先检查其目的IP
3. 如果目的IP在路由器所属的子网内, 报文被直接发送给目标主机. 否则发送给下一个路由器. 
4. 如此往复直到抵达目标IP

# 数据链路层

## 以太网帧格式

以太网帧是以太网中数据传输的基本单位，主要由以下几个部分组成：

| 字段            | 长度        | 作用                            |
| ------------- | --------- | ----------------------------- |
| 前导码（Preamble） | 7字节       | 用于发送方和接收方的时钟同步。               |
| 帧开始定界符（SFD）   | 1字节       | 标识以太网帧的开始。                    |
| 目的MAC地址       | 6字节       | 标识数据帧的接收方。                    |
| 源MAC地址        | 6字节       | 标识数据帧的发送方。                    |
| 类型/长度字段       | 2字节       | 标识上层协议类型或数据字段长度. 例如ARP/RARP协议 |
| 数据字段（Data）    | 46～1500字节 | 存放上层协议传输的数据，不足46字节时需要填充。      |
| 帧校验序列（FCS）    | 4字节       | 使用CRC校验，检测数据帧在传输过程中是否发生错误。    |

在数据字段中含有ARP/RARP请求与应答的数据段. 

## MTU
以太网帧中的数据长度规定最小46字节,最大1500字节,ARP数据包的长度不够46字节,要在后面补填充位; 最大值1500称为以太网的最大传输单元(MTU),不同的网络类型有不同的MTU.

如果数据包过大, 需要对数据包进行分片
- 每个小包的IP协议头的3位标志字段中, 第2位置为0, 表示允许分片, 第3位来表示结束标记(当前是 否是最后一个小包, 是的话置为1, 否则置为0);
- 到达对端时再将这些小包, 会按顺序重组, 拼装到一起返回给传输层;

## ARP协议

由于实际在网络中寻找主机时依赖的是MAC地址而非IP地址, 故需要建立IP地址与MAC地址的映射关系. 

> 需要强调的是ARP不是一个单纯的数据链路层的协议, 而是一个介于数据链路层和网络层之间的协议.

**ARP协议工作流程**
1. 源主机广播寻找目的IP的MAC地址
2. 目的主机收到广播的ARP请求, 其IP与源主机寻找的IP地址相符, 则向源主机发送一个ARP应答数据包, 其中包含目的主机的MAC地址. 
- 为了提高效率并减少广播寻找对端MAC的频率, 每个主机会维护一个ARP缓存表以保存最近访问过的目标主机的MAC地址. 该缓存表中表项的有效时间一般为20min. 
### ARP数据报格式

|字段|长度|作用|
|---|---|---|
|硬件类型|2字节|指明硬件类型，如以太网。|
|协议类型|2字节|指明协议类型，如IPv4。|
|硬件地址长度|1字节|表示MAC地址的长度。|
|协议地址长度|1字节|表示IP地址的长度。|
|操作码|2字节|区分ARP请求（1）和ARP应答（2）。|
|发送方MAC地址|6字节|发送方的硬件地址。|
|发送方IP地址|4字节|发送方的IP地址。|
|目标MAC地址|6字节|目标主机的硬件地址。|
|目标IP地址|4字节|目标主机的IP地址。|
主机接收到ARP请求时会首先根据操作码区分请求与应答.
