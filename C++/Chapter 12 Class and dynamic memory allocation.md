## 1. 静态成员变量

- 无论创建多少对象，程序都只创建一个**静态类变量副本**，所有对象共享该静态成员。
    
- **静态数据成员不能在类声明中初始化**，因为类声明只是描述，不分配内存。（C++17开始支持类内初始化）。
    

```cpp
int StringBad::num_strings = 0;  // 在类外初始化
```

- 但若静态成员是 **const 整数** 或 **enum**，则可在类中直接初始化。
	
- enum成员常被作为常量组，更安全。
    

---

## 2. 构造与析构函数

- 字符串等动态数据并不保存在对象中，而是单独存在于**堆内存**中。
    
- 构造函数中若使用 `new` 分配内存，则析构函数中必须用 `delete` 释放内存。
    
- 若未显式调用析构函数，程序会在 **代码块结束或 `main()` 结束时自动调用**。
    

---

## 3. 复制构造函数

- 复制构造函数由编译器自动生成，与默认构造函数不同。
    
- 触发条件：
    
    - 用一个对象初始化另一个新对象。
        
    - 函数返回对象时。
        
    - 按值传递对象时（生成临时副本）。
        

🟢 建议：**尽可能使用引用传递对象**，避免生成临时副本。

---

## 4. 赋值运算符重载与自赋值问题

- 编译器也会自动生成赋值运算符（`operator=`），但往往不安全。
    
- 手动重载时需注意：
    
    - 先用 `delete` 释放旧指针指向的内存。
        
    - 检查 **是否为自赋值**，以避免释放自身内容。
        

---

## 5. 深拷贝与浅拷贝

- 若构造函数中使用 `new` 分配了指针成员，复制构造函数中也应使用 `new` 创建其副本，这称为**深拷贝**。
    
- 否则多个对象共享同一块内存，销毁时将导致错误。
    

---

## 6. `nullptr` 代替 `NULL`

- C++11 引入 `nullptr`，类型安全，优先使用。
    

---

## 7. 静态成员函数

- 使用 `static` 声明的成员函数：
    
    - 不能通过对象调用，甚至不能用this指针
    - 只能通过类名调用。本质上属于整个类, 而不是某个对象.
        
    - **只能访问静态数据成员**。
        

---

## 8. 运算符重载技巧

- `=` 与 `[]` 的重载较特殊，详见 _C++ Primer Plus_ p.364。
    
- 重载 `=` 时必须：
    
    - 释放旧内存（`delete`），
        
    - 再重新分配新空间。
        

---

## 9. 析构函数与 `delete` 匹配

- `new` 与 `delete` 必须匹配。
    
- 若对象中包含非 `new` 分配的内存（如字符串字面值），则在析构中使用 `delete` 释放会导致**未定义行为**。
    

---

## 10. 引用与对象传递

- 合理使用引用可避免非法调用复制构造函数。
    
- 若按值传递对象，且对象含指针成员，则在函数结束时析构函数被调用会导致悬空指针问题。
    

---

## 11. 使用 `new` 创建对象

```cpp
String* sleep = new String;               // 调用默认构造函数
String* gleep = new String("my my");     // 调用带参构造函数
```

---

## 12. 定位 new 运算符

- 使用 **placement new** 时要特别注意不同形式的调用差异，详见 p.373。
    

---

## 13. 析构与构造匹配原则

- 若析构函数中使用 `delete` 释放内存，则：
    
    - 每个构造函数都必须用 `new` 初始化指针成员，
        
    - 或在没有分配时将其设为 `nullptr`。

## 15. 成员初始化列表（C++11）

构造函数定义时可直接初始化成员：

```cpp
Classy::Classy(int n, int m) : mem1(n), mem2(0), mem3(n * m + 2) {
    // ...
}
```

**注意：**

- 仅能用于构造函数。
    
- 必须使用此方式初始化：
    
    - **非静态 const 成员**
        
    - **引用成员**
        
- 初始化顺序遵循**类中成员定义顺序**，与参数顺序无关。
    

---

**Summary：**  
- 静态成员全局共享，必须类外初始化；构造/析构需匹配 `new` 与 `delete`；  
- 复制与赋值应实现深拷贝并防止自赋值；  
- 引用传参可避免析构问题；  
- 成员初始化列表更高效且是初始化 const 与引用成员的唯一方式。
