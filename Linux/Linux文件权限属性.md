## 核心规律：把权限当“加法”

每一位数字其实是这三种权限的组合：

|权限|符号|数值|
|---|---|---|
|读|r|4|
|写|w|2|
|执行|x|1|

 **本质：二进制位权（4-2-1）**

所以：

- `rwx = 4+2+1 = 7`
- `rw- = 4+2 = 6`
- `r-x = 4+1 = 5`
- `r-- = 4 = 4`

--- 

## 最常用权限（重点记这几个）


|数字|含义|场景|
|---|---|---|
|7|rwx|完全控制|
|6|rw-|可读写|
|5|r-x|可读执行|
|4|r--|只读|
|0|---|无权限|

> 实际上没人用这些乱七八糟的组合754、652、713……


## 一个常见的坑

当我即是文件的拥有者, 又属于当前文件的所属组时, 把我个人的对文件的一些权限砍掉, 即使我拥有组权限, 我也不能操作文件. 原因是: 
**用户访问文件时, 确定自己相对于文件的角色, 权限只会验证一次.**  

# Linux 目录权限

- **进入目录**（`cd`）：需要执行权限 `x`。
- **读取目录内容**（`ls`）：需要读取权限 `r`；查看文件详细信息通常还需要 `x`。
- **修改目录内容**（新建、删除、重命名文件）：需要写权限 `w` 和执行权限 `x`。
*注意, 修改目录内容不包括对于目录中文件的读写. 只包括对文件的创建与删除*

# 粘滞位（Sticky Bit）

粘滞位主要用于多人可写的目录。设置后，目录中的文件只能由以下用户删除或重命名：

- 文件所有者
- 目录所有者
- `root`

```bash
chmod +t 目录名       # 添加粘滞位
chmod -t 目录名       # 移除粘滞位
chmod 1777 目录名     # 数字表示法，最高位的 1 表示粘滞位
```

例如 `/tmp` 通常具有 `1777` 权限。使用 `ls -ld` 查看时，其他用户的执行位会显示为 `t`；若原本没有执行权限，则显示为 `T`。
