## 静态库（Static Library）制作与使用

#### 一、 核心制作流程（基于图片内容）

**1. 编译生成目标文件 (.o)** 将所有源代码编译成不可执行的二进制目标文件。

- **命令：** `gcc -c add.c -o add.o`
    
- **注意：** 此时不进行链接，仅检查语法并生成机器码。
    

**2. 使用 `ar` 工具打包成静态库 (.a)** `ar` (archiver) 是 Linux 下专门用于创建、修改和提取归档文件的工具。

- **命令：** `ar rcs libmymath.a add.o sub.o div.o`
    
- **参数含义：**
    
    - `r`：将文件插入库中（替换已有文件）。
        
    - `c`：建立库文件。
        
    - `s`：建立索引，加快链接速度。
        
- **命名规范：** 库名必须以 `lib` 开头，以 `.a` 结尾。
    

**3. 将静态库编译进可执行程序**

- **命令：** `gcc test.c libmymath.a -o a.out`
    
- **本质：** 链接器会将静态库中被 `test.c` 引用到的函数代码直接拷贝到 `a.out` 中。程序运行阶段不再依赖 `.a` 文件。

#### 二、 进阶：头文件 (.h) 的对应与重要性

在实际工程中，仅仅提供 `.a` 文件是不够的。头文件是库的“说明书”和“接口”。编译器在处理 `test.c` 时需要知道库中函数的原型，否则会报警告或错误。

**配合头文件的编译命令：** 如果头文件在 `include` 目录下，库在 `lib` 目录下，编译命令应进化为： `gcc main.c -I ./include -L ./lib -lmymath -o app`

- `-I`：指定头文件搜索路径。
    
- `-L`：指定库文件搜索路径。
    
- `-l`：指定库名（切记去掉 `lib` 前缀和 `.a` 后缀）。



## 动态库制作及使用四步法

### 1. 编译生成位移无关的目标文件 (.o)

- **命令：** `gcc -c add.c -o add.o -fPIC`
    
- **关键点：** `-fPIC` (Position Independent Code)。
    
- **底层逻辑：** 动态库在内存中的加载地址是不固定的。使用 `-fPIC` 确保生成的机器码不使用绝对地址，从而使代码可以在多个进程间共享而无需修改。
    

### 2. 生成动态链接库 (.so)

- **命令：** `gcc -shared -o lib库名.so add.o sub.o div.o`
    
- **关键点：** `-shared` 告诉编译器生成的是共享库而非可执行文件。
    
- **规范：** 库名必须以 `lib` 开头，以 `.so` 结尾。
    

### 3. 编译并链接到可执行程序

- **命令：** `gcc test.c -o a.out -lmymath -L./lib`
    
- **参数拆解：**
    
    - `-l`：指定库名（**注意：** 需去掉 `lib` 前缀和 `.so` 后缀，如 `libmymath.so` 写作 `mymath`）。
        
    - `-L`：指定库文件所在的目录路径。
    - 注意可以添加参数`-I`, 例如`-I ./Inc`, inc指的是头文件的目录. 库最好声明完整的头文件防止函数声明错误. 
        
- **思维陷阱：** 这一步仅仅是告诉**静态链接器**库的位置，以便验证函数签名并将其记录在可执行文件的符号表中，但库的内容并没有被拷贝进 `a.out`。
    

### 4. 运行时环境配置（解决加载报错）

这是最容易出错的一步。即使编译成功，运行 `./a.out` 时也常因**动态链接器**（Dynamic Linker）找不到库文件而报错。

- **问题根源：** 链接器（编译时）与动态加载器（运行时）是两个独立的实体。后者默认只在标准路径（如 `/lib`, `/usr/lib`）查找。
    
- **解决方案（环境变量法）：**
    
    - **临时生效：** `export LD_LIBRARY_PATH=动态库绝对路径`。仅对当前终端有效。
        
    - **永久生效：** 将上述命令写入 `~/.bashrc` 配置文件，并执行 `source ~/.bashrc` 刷新环境。或者重启终端.
- **滥竽充数法**: 直接把库文件拷贝到系统的库目录下. 要记得删除bashrc里的配置文件. *不太推荐这样做, 用户级别的文件尽量不要放进系统目录里*

>Tips: `ldd programname`可以查看该程序使用了哪些库文件. 如果加载失败, 库目录就会为空. 可以用来测试库的位置是否被识别.
