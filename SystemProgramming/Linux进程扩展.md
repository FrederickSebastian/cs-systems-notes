# 进程状态

广义上的OS进程可以分为以下几种: 创建, 就绪, 运行, 阻塞, 僵尸, 就绪挂起, 阻塞挂起, 结束状态.

在Linux操作系统下, 进程的状态由几个字母表示:

1. S, Sleep睡眠状态, 进程在等待事件完成, 此状态可以被打断. 
2. R, Run运行状态. **但并不意味着进程一定在运行队列中, 也可能就绪队列中**
3. D, Disk Sleep, 磁盘睡眠状态, 不可被打断, 因为进程正在等待磁盘处理数据. 
4. T, Stop暂停状态, 通常由暂停信号发出, 可以被恢复. 
5. X, 死亡状态, 通常看不到.
具体对应关系如下:

| 字母  | 含义                           | 对应经典 OS 状态  |
| --- | ---------------------------- | ----------- |
| `R` | Running / Runnable           | **运行 + 就绪** |
| `S` | Interruptible Sleep，可中断睡眠    | 阻塞          |
| `D` | Uninterruptible Sleep，不可中断睡眠 | 阻塞          |
| `T` | Stopped，停止                   | 暂停          |
| `t` | Tracing Stop，被调试器跟踪停止        | 暂停          |
| `Z` | Zombie，僵尸                    | 僵尸          |
| `X` | Dead，死亡                      | 结束          |
| `I` | Idle，主要用于空闲内核线程              | 特殊状态        |

# 进程优先级

Linux作为分时操作系统, 进程存在被执行的优先级. 

## 进程优先级在Linux中的表示
使用`ps`命令, `PRI`与`NI`列共同决定进程的优先级别. 进程优先级别的判定遵循以下几点: 
1. 进程优先级别越高, `PRI`值越小. 进程优先级虽然由两个变量决定, 但是最终只需要检查`PRI`值就可以确定优先级.
2. `NI`值表示偏移量(bias), 表示目前进程的`PRI`值在原本的值上偏移了多少. 
3. 使用`NI`改变`PRI`时, 始终在`PRI = 80`的基础上做偏移. 
4. `NI`的取值范围是-20 -- 19.

# Linux的进程调度机制
*以下内容基于Linux2.6内核进程O(1)调度队列设计*

## 调度队列内核计中的设计
1. 已知调度队列本质上是一个链表. Linux kernel并没有设计一个链表直接把task_struct放进去, 而是在task_struct中内嵌一个链表结构体, 含有指向下一个和上一个task_struct的指针. 以此形成调度队列. 
*如此设计的好处是: 这一套链表处理体系可以用来处理所有含有这个结构的系统数据结构*
2. 通常, 链表指向下一个task_struct时, 并不指向它的内存首地址. 这时需要用内存偏移来获得task_struct的内存首地址. 该过程类似于结构体的内存偏移.
3. runqueue是运行队列, 是一个结构体, 其上含有调度队列链表的首地址. runqueue内核控制的内存空间中. 
4. runqueue中含有两个调度队列链表, 第一个是活跃队列, 第二个是过期队列.

## 活跃队列与过期队列
1. 一个进程耗尽时间片后, 会被从活跃队列上摘下, 挂上过期队列
2. 活跃队列消耗完所有进程后, 从过期队列上取出进程开始执行, 也就是活跃队列变成过期队列, 过期队列反之.
3. 当有新进程来临时, 不会被直接挂到活跃队列上, 而是被挂到过期队列上.
4. 活跃队列中的进程被改变优先级时, 进程的“动态优先级”通常会在时间片耗尽时重新计算。这个时机往往正好就是任务从 active 队列取出、准备进入 expired 队列的时机. 此时, `NI`值会参与计算. 

## 进程优先级与调度队列
1. 调度队列runqueue的设计类似于简单链式哈希表的设计. 每一个节点上对应一个链表. 
2. 获得进程的优先级值以后, 该值模队列的长度, 便可以被放进对应的链表中. 
3. 这样便计算出了进程的优先级. 后续调度时, 时间复杂度接近于哈希O(1)
4. 后续的Linux内核改进了这个设计, 所以现在的Linux内核已经不采用这个结构体了

# 父进程与子进程
其资源读时共享, 写时拷贝
1. 创建子进程以前, 父进程的代码段(页表)是只读的, 数据段(页表, 下同)是读写的. 
2. 创建子进程后, 二者全部变成只读的. 
3. 父进程或者子进程有写入数据, 数据段会被会复制出来一份, 然后数据段变成可写的.
4. 代码段始终是共享且只读的.

# 进程退出

## 进程的退出状态
进程退出时, 其执行是否有误, 由return值与信号共同决定.
1. 返回值为0, 信号为0, 正常退出
2. 返回值不为0, 信号值为0, 异常退出
3. 返回值为0, 信号不为0, 异常退出, 此时返回值无意义.

## wait_pid的传出参数status
其第二个参数`status`是传出参数, 但是不能将其作为整形处理. 
它本质是一个位图, 前8位记录信号, 后8位记录返回值
使用时, 用如下两个宏函数简化操作:
1. WIFEXITED(status): 若为正常终止子进程返回的状态，则为真。（查看进程 是否是正常退出） 
2. WEXITSTATUS(status): 若WIFEXITED非零，提取子进程退出码。（查看进程的退出码）
