# ELF文件
ELF是Linux的一种二进制文件格式. 主要用于以下四类文件:
1. 目标文件(.o)
2. 可执行文件
3. 共享目标文件(例如动态链接库)
4. Core Dump

## ELF文件结构
1. ELF Header: 描述文件的主要特性与定位文件的其他部分
2. 程序头表Program header table: 列举所有段与其树形. 其中记录每个段的开始位置与位移(offset)
3. 节头表Section header table: 对每一节的描述
4. 节: 具体数据

> 链接阶段, 链接器会把多个ELF相应结构的数据合并

## 节与段
节(Section)是 ELF 文件中组织代码和数据的基本单位. 节服务于编译器与链接器. 利于链接时组织代码以及处理重定位

段(Segment)是ELF文件加载到内存时的组织单位. 段有权限. 主要服务于操作系统的加载器.

> 一个段可以包含多个节. 链接器通常把多个节组合到一个段中. 这样做看可以对齐内存, 减少页面碎片, 提高内存效率

# 静态链接
链接器会根据`.o`文件或者静态库中的重定位表找到那些需要被重定位的函数全局变量，从而修正它们的地址。这就是静态链接的过程。

## 静态链接的全过程
1. 编译器生成`.o`, 并在符号表中记录已定义和未定义的符号
2. 在需要修正的引用(例如未找到定义的函数)保留占位字段, 并生成重定位记录
3. 链接器合并, 布局各节, 利用符号表找到定义
4. 链接器处理重定位记录, 找到待修正字段, 填入地址或者位移.

### 符号表
记录调用函数的名字及其定义情况. 在汇编阶段生成. 
未定义的函数的地址不一定被标为0. 可能是一个占位符. 

### 重定位表
记录应当修正哪些函数的地址以及如何修正. 在汇编阶段生成
重定位表就保存这样的记录：
`| 要修正的位置 | 引用哪个符号 | 按什么规则修正 |`

**为什么对于同一个函数, 链接阶段装入的地址不同?**
因为CPU中记录的是下一条指令的地址. 为了直接指向该函数的地址, 需要计算相对偏移量. 即函数的虚拟地址是固定的, 但偏移量不是固定的.

# 动态链接

> ELF文件中通常直接保存了虚拟内存地址信息.

C/C++程序中，当程序开始执行时，它首先并不会直接跳转到 main 函数。实际上，程序的入口点 是 _start ，这是一个由C运行时库（通常是glibc）或链接器（如ld）提供的特殊函数。 在 _start 函数中，会执行一系列初始化操作，这些操作包括： 
1. 设置堆栈：为程序创建一个初始的堆栈环境。 
2. 初始化数据段：将程序的数据段（如全局变量和静态变量）从初始化数据段复制到相应的内存位置，并清零未初始化的数据段。

## 动态库的调用
1. 库被映射到当前进程的虚拟地址空间中. 
2. 调用时, 从代码区跳转到共享区, 调用完毕再跳转回代码区. 
3. 由于代码区无法被修改, 故引入全局偏移量表GOT

## GOT
1. 该表在数据节中. 存放函数的跳转地址. 
2. GOT表的位置在虚拟内存中是固定的
3. 调用函数时先查表. 然后跳转到对应地址. 
4. 这种方式实现的动态链接就被叫做 PIC 地址无关代码 。换句说，我们的动态库不需要做任何修改，被加载到任意内存地址都能够正常运行，并且能够被所有程共享，这也是为什么之前我们给编译器指定-fPIC参数的原因，*PIC=相对编址+GOT。*
