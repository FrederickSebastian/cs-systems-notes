# GDB 常用调试命令总结

### 1. 程序运行

```
run / r          # 从头运行程序
start            # 运行并停在 main 函数开头
continue / c     # 继续运行，直到下一个断点
quit / q         # 退出 GDB
```

### 2. 查看源码

```
list / l                 # 查看当前位置附近源码
list 函数名              # 查看指定函数
list 文件名:行号         # 查看指定位置
```

### 3. 单步调试

```
next / n         # 单步执行，不进入函数
step / s         # 单步执行，进入函数
finish           # 执行完当前函数并返回
until 行号       # 执行到指定行，常用于跳出循环
```

### 4. 断点

```
break / b 行号            # 在指定行设置断点
break / b 函数名          # 在函数入口设置断点
b 文件名:行号             # 在指定文件设置断点

info break / i b          # 查看所有断点
delete N                  # 删除编号 N 的断点
disable N                 # 禁用断点
enable N                  # 启用断点
```

条件断点：

```
b 20 if i == 100
condition 1 i == 100
```

表示只有满足条件时才停止。

### 5. 查看和修改变量

```
print / p x           # 查看变量或表达式
display x             # 每次程序停止时自动显示 x
undisplay N           # 取消编号 N 的自动显示
info locals           # 查看当前函数的局部变量
info args             # 查看当前函数参数
set var x = 10        # 修改变量值
```

### 6. 监视变量

```
watch x           # x 被修改时停止
rwatch x          # x 被读取时停止
awatch x          # x 被读取或修改时停止
```

`watch` 很适合排查“变量到底在哪里被改坏了”。

### 7. 查看函数调用栈

```
backtrace / bt        # 查看函数调用栈
frame N / f N         # 切换到第 N 个栈帧
up                    # 切换到上层调用者
down                  # 切换到下层栈帧
```

程序发生 `Segmentation Fault` 时常用：

```
bt
frame N
info args
info locals
p 变量
```

### 8. 查看内存

```
x/格式 地址
```

常见：

```
x/10dw arr       # 查看 10 个十进制整数
x/16xb ptr       # 查看 16 个字节的十六进制内容
x/s str          # 按字符串查看
```

**易错点**
1. 默认的情况下，make命令会在当前目录下按顺序找寻文件名为“GNUmakefile”、“makefile”、“Makefile”的文件， 找到了解释这个文件
2. 在Makefile不可以使用include关键字把别的Makefile包含进来

## 补充知识
1. 伪目标: 让make忽略源文件与可执行目标的M(修改)时间的对比, 用`.PHONY`修饰.
2. 为什么编译目标不被`PHONY`修饰: 为了提高编译效率, 编译目标需要对比可执行目标的修改时间以跳过没有被修改的文件. 而`PHONY`修饰的目标总是被执行. 故不能跳过被修改的文件. 
3. makefile中在命令前添加`@`符号让该指令不在terminal上回显

### makefile的栈结构推导
1. 直接执行 make 时，通常只构建 Makefile 中的默认目标（一般是第一个目标）以及它所依赖的目标，不会自动生成所有目标
2. 找到第一个目标时, 会把其对应的目标文件作为最终的文件
3. 如果它的依赖项不存在, 就把他的依赖方法入栈, 寻找该依赖方法的依赖项
4. 以此类推, 直至最终编译目标文件. 如果最后被以来的文件找不到, 会直接报错.
