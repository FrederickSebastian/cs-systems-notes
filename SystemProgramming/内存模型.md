**进程虚拟地址空间布局**

# 一、虚拟内存的基本概念

在 32 位系统中：

- 地址总线：32 位 → 可寻址空间 = **4GB**
    
- 每个进程看到的是**独立的虚拟地址空间**
    
> **我们在C程序中看到的内存地址, 是虚拟内存地址. 实际的物理地址被操作系统隐藏, 用户无法检查. ** 

典型划分（以 Linux 为例）：

```
0x00000000 ────────────────
           用户空间（User Space）≈ 3GB
0xC0000000 ────────────────
           内核空间（Kernel Space）≈ 1GB
0xFFFFFFFF ────────────────
```

- **0x00000000 ~ 0xBFFFFFFF** → 用户态
    
- **0xC0000000 ~ 0xFFFFFFFF** → 内核态（所有进程共享）
    
## 虚拟内存在Linux内核中的实现
在task_struct中, 实现了一个结构体(内存描述符), 结构体内很多组unsigned long整数, 每组包含start&&end, 用于标识每个内存区域的起始与终止位置.
>对于不连续的堆空间, 内核用了多个结构体维护多个的空间. 每次分配内存都会创建一个相应的结构体.

# 二、用户空间的典型布局（从低地址到高地址）



```
低地址
│
├── text（代码段）
├── rodata（只读数据）
├── data（已初始化全局变量）
├── bss（未初始化全局变量）
├── heap（堆，向上增长）
│
│   ... 空闲区 ...
│
├── mmap区（动态映射区）
│
├── stack（栈，向下增长）
│
高地址
```

下面逐个解释。

---

## 1. text 段（代码段）

- 存放：**程序机器指令**
    
- 特点：
    
    - 只读（防止被修改）
        
    - 可共享（多个进程共享同一程序代码）
        

例如：

```c
int main() { return 0; }
```

编译后生成的指令就在 text 段。

---

## 2. data / bss 段

### data（已初始化数据）

```c
int a = 10;
```

- 已经赋值
    
- 存在可执行文件中
    

---

### bss（未初始化数据）

```c
int b;
```

- 默认初始化为 0
    
- 不占用可执行文件空间（运行时分配）
    

---

## 3. heap（堆）

- 用于：**动态内存分配**
    
- API：
    
    - `malloc / free`
        
    - `new / delete`
        
- 增长方向：**向高地址增长**
    

```
heap ↑
```

底层实现：

- 早期：`brk/sbrk`
    
- 现代：`mmap`
    

---

## 4. mmap 区（内存映射区）

用途：

- 动态库加载（.so）
    
- 文件映射
    
- 大块内存分配（malloc 可能走这里）
    

特点：

- 地址不连续
    
- 由内核管理
    

---

## 5. stack（栈）

- 用于：
    
    - 函数调用
        
    - 局部变量
        
- 增长方向：**向低地址增长**
    

```
stack ↓
```

例如：

```c
void f() {
    int x = 10;
}
```

`x` 在栈上。

---

# 三、关键特性（必须理解）

## 1. 堆和栈“对向增长”

```
heap ↑        ↓ stack
     中间可能发生碰撞
```

如果两者相遇 → **内存耗尽（OOM / 段错误）**

---

## 2. 虚拟内存 ≠ 物理内存

操作系统通过：

- 页表（Page Table）
    
- MMU（内存管理单元）
    

实现：

```
虚拟地址 → 物理地址
```

带来的好处：

- 每个进程隔离
    
- 支持内存扩展（swap）
    
- 提供安全性
    

---

## 3. 内核空间的作用

内核区（1GB）用于：

- 系统调用
    
- 进程调度
    
- 设备驱动
    
- 内存管理本身
    

特点：

- 所有进程共享
    
- 仅内核态可访问
    

---

# 四、为什么是 3G / 1G 划分？

这是设计权衡：

|划分|含义|
|---|---|
|3GB 用户|让应用有足够空间|
|1GB 内核|保证内核稳定运行|

有些系统支持调整：

- 2G / 2G（Windows）
    
- 3G / 1G（Linux 常见）

# 六、常见面试/考点总结

你这块已经涉及核心知识点，可以进一步注意：

### 1. malloc 一定在 heap 吗？

不一定：

- 小块 → heap（brk）
    
- 大块 → mmap
    

---

### 2. 栈溢出 vs 堆溢出

- 栈溢出：递归过深
    
- 堆溢出：malloc 过多
    

---

### 3. 为什么需要虚拟内存？

- 隔离进程
    
- 简化编程（每个进程都认为自己有完整 4GB）
    
- 支持懒加载（demand paging）
    

---

### 4. 64 位系统变化

- 地址空间极大（理论 2^64）
    
- 实际使用（如 48 位虚拟地址）
    

---

# 七、总结

应用程序的内存管理本质是：

> 操作系统为每个进程构建一个独立的虚拟地址空间，并通过分页机制，将 text/data/heap/stack 等区域映射到物理内存，实现隔离、安全与高效管理。

## 虚拟内存空间与页表解决了什么问题

1. 当内存越界访问时, 可以利用虚拟内存空间检查是否越界, 从而保护物理内存. 
2. 提高了物理内存的利用率. 通过页表机制, 可以把虚拟内存空间不同的内存区域映射到不同的物理内存空间.
3. 提高了物理内存利用率. 通过懒加载机制(使用时再分配相应的内存), 把空闲区域留给其他进程. 进程管理模块和内存管理模块就完成了解耦合.
