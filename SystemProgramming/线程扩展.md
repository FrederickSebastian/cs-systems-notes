
## 进程与线程

- 进程是资源分配的基本单位
- 线程是调度的基本单位


## 一、Linux 线程的创建机制

Linux 使用 `task_struct` 描述一个任务，进程和线程都有各自独立的 `task_struct`。

调用 `pthread_create()` 创建线程时，底层通过 `clone()` 或 `clone3()` 等机制创建新任务。

主要过程：

1. `copy_process()` 负责创建新任务。
    
2. `dup_task_struct()` 复制并初始化新的 `task_struct`。
    
3. 通过 `CLONE_VM` 标志，使新线程与原线程共享 `mm_struct`。
    
4. 为新线程设置独立的用户态栈、内核栈和 CPU 寄存器上下文。
    
5. 将新线程加入调度系统。
    

其中，`task_struct` 的 `mm` 指针指向 `mm_struct`，用于描述任务的虚拟地址空间。

```
线程 1 → task_struct 1 ──┐
                         ├── mm_struct
线程 2 → task_struct 2 ──┘
```

结论：线程拥有独立的 `task_struct`，但共享同一个 `mm_struct`，因此共享虚拟地址空间。

## 二、线程之间的资源共享

|资源|是否共享|
|---|---|
|`task_struct`|不共享|
|`mm_struct`|共享|
|虚拟地址空间、页表|共享|
|代码段、数据段、堆|共享|
|用户态栈|各自拥有独立的栈区域|
|内核栈|不共享|
|CPU 寄存器上下文|不共享|
|线程 ID（TID）|不共享|
|文件描述符表|通常共享|

注意：虽然各线程使用不同的栈区域，但这些栈都位于同一个虚拟地址空间中。 因此，一个线程可以通过有效指针访问另一个线程的栈内存。

**核心: 线程拥有独立的上下文(寄存器)与栈空间**

## 三、线程与函数调用栈

每个线程拥有自己的栈空间，每次普通函数调用通常会在当前线程的栈中建立栈帧（Stack Frame）。

例如：

```
void B() {
    int y = 20;
}

void *A(void *arg) {
    int x = 10;
    B();
    return NULL;
}
```

假设通过 `pthread_create()` 创建 10 个线程，全部执行函数 A，而 A 又调用 B。

那么每个线程都有独立的 A、B 栈帧：

```
线程 1 的栈          线程 2 的栈          ... 线程 10 的栈
┌──────────┐        ┌──────────┐          ┌──────────┐
│ B 栈帧   │        │ B 栈帧   │          │ B 栈帧   │
│ y = 20   │        │ y = 20   │          │ y = 20   │
├──────────┤        ├──────────┤          ├──────────┤
│ A 栈帧   │        │ A 栈帧   │          │ A 栈帧   │
│ x = 10   │        │ x = 10   │          │ x = 10   │
└──────────┘        └──────────┘          └──────────┘
```

- 10 个线程共享同一份 A、B 函数的机器代码。
    
- 每个线程有独立的栈指针（x86-64 架构下为 `RSP`）。
    
- A 调用 B 时，B 继续使用当前线程的栈空间。
    
- B 返回后，其栈帧失效，继续执行 A。
    
- 如果 B 递归调用自身，每次递归通常会产生新的栈帧。
    

实际编译时，编译器可能进行内联、尾调用优化或寄存器分配，因此不一定存在对应的物理栈帧。

## 四、函数中的变量是否共享？

|变量类型|存储位置|是否共享|
|---|---|---|
|普通局部变量|通常在栈或寄存器中|各次函数调用独立|
|`static` 局部变量|静态存储区|共享|
|全局变量|静态存储区|共享|
|`malloc()` 分配的内存|堆|可通过指针共享|
|`_Thread_local` 变量|线程局部存储区（TLS）|每个线程独立|

多个线程同时修改共享变量时，需要考虑数据竞争，必要时使用互斥锁、原子操作等同步机制。


## 线程在Linux中的实现

- Linux内核没有实现线程, 线程在Linux中表现为轻量级进程(LWP)
- `pthread`线程库封装了LWP实现了用户级线程. 
- 事实上, 线程的的栈空间在`Pthread`动态库库的内存空间中, 并映射到进程的虚拟地址空间中.
### pthread_t与LWP
- 每一个LWP有对应的编号. 可以用`ps -L`检查
- `pthread_t`是线程库实现的线程号, 实质上是线程的虚拟地址空间的起始地址. 它并非系统级的变量, 无法在Linux中查看. 
- `pthread_self()`可以查看自身线程的线程id

# 线程同步

### 1. 为什么生产者和消费者操作时都需要加锁？

生产者和消费者会并发访问共享数据，如果不加锁，可能发生数据竞争，导致数据错误。互斥锁可以保证同一时刻只有一个线程访问和修改共享状态，同时确保条件判断与数据操作的原子性。

### 2. 为什么 pthread_cond_wait() 使用 while 而不是 if？

因为 `pthread_cond_wait()` 返回时，等待条件不一定仍然成立。`if` 只判断一次，唤醒后直接继续执行；`while` 会重新检查条件，如果仍然不满足，就再次等待，避免错误操作。

可能发生以下情况：

1. C1 发现 `size == 0`，调用 `pthread_cond_wait()`，释放互斥锁并进入等待。
    
2. P 生产一个数据，使 `size = 1`。
    
3. P 调用 `pthread_cond_signal()`，唤醒 C1。
    
4. 此时 C1 尚未重新获得互斥锁。
    
5. C2 抢先获得互斥锁，发现 `size == 1`，消费数据，使 `size = 0`。
    
6. C2 释放互斥锁。
    
7. C1 终于获得互斥锁，`pthread_cond_wait()` 返回。
    

此时虽然 C1 被正常唤醒，但缓冲区已经被 C2 消费完毕。

### 3. pthread_cond_signal() 只唤醒一个线程，为何需要 while

因为 `pthread_cond_signal()` 只负责唤醒线程，不保证被唤醒线程优先获得互斥锁。例如 C1 被唤醒后，C2 可能抢先获得锁并消费数据，导致 C1 获得锁时缓冲区已经为空。因此需要使用 `while` 重新检查条件。

### 4. 什么是虚假唤醒

虚假唤醒是指线程在没有收到对应条件变量通知的情况下，`pthread_cond_wait()` 仍然返回。POSIX 允许这种行为，可能由线程库内部的并发竞争、同步机制等原因引起。因此必须使用 `while` 检查条件，防止线程在条件不满足时继续执行。

## 5. 为什么需要条件变量

考虑如下不使用条件变量实现的生产者-消费者代码: 
```c++
pthread_mutex_lock(&mutex);

while (count == 0) {
    pthread_mutex_unlock(&mutex);
    // 不断检查是否有数据
    pthread_mutex_lock(&mutex);
}

// 消费数据

pthread_mutex_unlock(&mutex);
```
- 频繁加锁解锁增加同步开销
- 大量轮询会占用CPU资源



# 线程回收
# 一、线程两种状态

- **Joinable（默认）**
    
    - 必须 `pthread_join`
        
    - 否则资源泄漏
        
- **Detached**
    
    - 自动回收资源
        
    - 不能 `join`
        

---

# 二、pthread_detach

```c
int pthread_detach(pthread_t thread);
```

**作用：**

- 将线程设为分离状态
    
- 线程结束后自动释放资源
    

**特点：**

- 不可再 `join`
    
- 适合无需返回结果的后台任务
    

---

# 三、pthread_join

```c
int pthread_join(pthread_t thread, void **retval);
```

**作用：**

- 等待线程结束（阻塞）
    
- 回收资源
    
- 获取返回值
    

---

# 四、pthread_cancel

```c
int pthread_cancel(pthread_t thread);
```

**作用：**

- 向线程发送“终止请求”
    

**特点：**

- 不保证立即终止（依赖取消点）(通常是在进入内核的时候)
    
- 不回收资源
    
- 通常需要配合 `join`
    

---

# 五、三者关系（核心）

- `cancel`：请求线程结束
    
- `join`：等待 + 回收
    
- `detach`：自动回收
    

---

# 六、典型组合

```c
pthread_cancel(tid);
pthread_join(tid, NULL);
```

含义：

1. 请求线程退出
    
2. 等待其结束
    
3. 回收资源
    

---

# 七、重要区别

|项目|cancel|join|detach|
|---|---|---|---|
|是否终止线程|请求终止|否|否|
|是否阻塞|否|是|否|
|是否回收资源|否|是|是|
|是否能获取返回值|否|是|否|

---

# 八、关键结论

- 线程结束 ≠ 资源释放
    
- 不 `join` 又不 `detach` ⇒ **资源泄漏**
    
- `cancel` 只是“请求”，不是强杀
    
- 生命周期 = **创建 + 终止 + 回收**
    

---

如果只记一句话：

> cancel 控制“结束”，join/detach 负责“收尸”。
