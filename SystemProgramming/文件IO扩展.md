**默认的Linux的三个文件描述符**

0->stdin;
1->stdout;
2->stderror;

## 文件描述符的使用规则
1. 每次分配文件描述符时, 默认选择序号最小的文件描述符. 
2. 一般从3开始分配. 如果手动关闭了0, 1, 2, 则会分配到序号最小的一个文件描述符. 
3. 例如, 如果手动关闭了stdin, 下一次open文件便会分配到文件描述符0. 

## 深入理解文件描述符
1. 在task_struct内部, 存在一个文件指针数组file_struct. 
2. 访问文件描述符时, 本质是访问数组的下标

## 如何理解一切皆文件
1. 在Linux中, 所有的设备被抽象为一个文件. 部分硬件的读写并不能直接通过系统调用访问. 
2. 内核为这些硬件抽象出了多个struct_file 结构体. 结构体中保存有函数指针. 函数指针指向驱动程式.
3. 当用户通过syscall访问硬件资源时, 系统调用访问这个结构体并使用其中保存的函数指针调用相关函数访问硬件资源
4. 以此做到接口的统一.


# 缓冲区机制
首先需要澄清系统级缓冲区和语言级缓冲区:
1. 系统级缓冲区: 使用syscall写入文件(Linux一切皆文件)时, 并不是直接将数据写入磁盘或者设备(CPU不能直接访问内存以外的硬件设备). 而是将数据写入内存中. 当时机合适时从内存写入文件. 
2. 语言级缓冲区: 以C语言为例. C封装了syscall, 例如`printf` `fgets`等众多函数. 这些函数内部定义了缓冲区. 
*事实上, 标准C库的IO函数底层仍然封装了sys_call和文件描述符*

## 文件级缓冲区的缓冲类型
1. 全缓冲
2. 行缓冲
3. 无缓冲
用户也可以手动调用函数刷新缓冲区
**(标准C的标准错误没有缓冲区)**

## 主动刷新缓冲区
| 函数 | 刷新的缓冲区 | 参数 |
|---|---|---|
| `fflush()` | C 标准库的 `FILE *` 用户态缓冲区 | `FILE *` |
| `fsync()` | 内核中的文件页缓存 / 系统级缓冲 | 文件描述符 `fd` |
| `fdatasync()` | 类似 `fsync()`，主要保证文件数据，减少不必要的元数据同步 | `fd` |
| `sync()` | 请求同步整个系统中所有文件系统的脏数据 | 无 |

另外, `exit()`函数退出时会强制刷新缓冲区, `_exit()`不会. 前者是标准C库, 后者是sys_call. 用`_exit()`退出时一些`printf()`可能不会打印. 

## 扩展
考察以下代码: 
```c
#include <stdio.h> 
#include <string.h>
int main() 
{
    const char *msg0="hello printf\n"; 
    const char *msg1="hello fwrite\n"; 
    const char *msg2="hello write\n";
    printf("%s", msg0); fwrite(msg1, strlen(msg0), 1, stdout); 
    write(1, msg2, strlen(msg2));

    fork();
    return 0;
}
```

然后对程式进行输出重定向` ./hello > file `, 打印结果为: 
```
hello write 
hello printf 
hello fwrite 
hello printf
hello fwrite
```
为什么会出现多个printf和fwrite, 原因如下
1. 当输出重定向到文件时, 由行缓冲变成全缓冲.
2. `write`没有缓冲区, 直接写入了程序. 
3. 由于`fork`创建子进程时, 标准C的缓冲区并未写满. 于是缓冲区也被复制了一份. 
4. 程序退出时, 父进程和子进程刷新缓冲区, 故标准C的输出被打印了两次.
